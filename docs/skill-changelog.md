# G1-D Skill 版本演进

这份文档保存原先内嵌在 `skills/*/SKILL.md` 里的版本演进记录。它**不是给模型看的**：
Skill 文档只描述当前规则，历史放在这里，避免每轮推理都重发一段变更日志。

行为规则本身在 `SKILL.md` 中完整保留，此处只记录"何时改的、之前是什么"。

## g1d-robot

| 版本 | 变更 |
| --- | --- |
| 0.1.17 | 视觉放置触发闭合改为**同一次读取里两个判据同时成立即闭合**，不再要求连续两轮确认。操作员要求一次即可触发。 |
| 0.1.16 | 视觉放置触发闭合改为**两路各判一半**：腕部画面判物体（是不是要抓的那个、有没有到夹爪口），头部画面判手指（是否张开、指间有没有东西、附近有没有人）。此前两路都要判断同一件事，抬臂姿态下头部看不到手指、腕部看不到物体，导致判据无法成立。 |
| 0.1.13 | `g1d.perception_state` **取消 5 秒环形缓冲**与 `history_s` / `max_history` 参数。状态存储只保留每路最新 1 帧，每次读到的就是当时最新的一帧；要看过程就按 `interval_s` 反复读取并自行比较。 |
| 0.1.12 | 增加**角度管理**：夹住时保持在测得停位（`blockage_rad` 即本次确认的夹持角度），下次命令前不变；放开用 `operation:"release"`——开到目标后自动闭回空夹静止位，夹爪不会留在张开状态。开爪目标与空夹静止位来自 `configs/device.yaml` 中经实测确认的 Dex1 行程，不再是 vendor 映射常量 5.4。 |
| 0.1.11 | 闭合改为**编码器感知**：边闭合边看实测角度，手指被物体挡住即停在该位置并保持，报告 `contact_detected` + `blockage_rad`；不再向零继续压。此前闭合是无条件走到 0，接触无法被观测。同时把 Dex1 开爪目标从 vendor 映射常量 5.4 改为操作员确认的实测行程。 |
| 0.1.6 | 增加 `g1d.observe`：只读的图像 + 机械臂状态组合观察包，与机械臂控制在同一 runtime 内。 |
| 0.1.5 | 增加显式肘部坐标模式 `elbows=[{side, mode: upper_arm\|world, angle_deg}]`，由 runtime 做角度换算，取代让调用方自己填原始编码器弧度。 |

### 视觉验证器的停用

`grasp_verifier` 在 0.1.12 前是闭合前的模型视觉闸门：Agent 必须先取 before 快照、送模型判断、通过后才允许闭合。停用原因：

- 它把"是否闭合"变成了一次额外的模型往返，而夹爪本身已有编码器接触判定这一机械证据；
- 模型对"手指间是否有物体"的回答不稳定，且 `verification_status` 容易被误读为物理验证；
- 保留实现于 `src/paos_g1d/manipulation/grasp_verifier.py` 供参考，但**不注册、不调用**。

现在的分工是：Action 报告机械结果（`mechanical_outcome` / `blockage_rad`），
视觉判断由 Agent 用 `image` 工具自行做出，两者不互相冒充。
